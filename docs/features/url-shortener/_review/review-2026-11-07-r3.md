### P1 — [stage-1] A visitor opening `GET /error` gets Boot's error JSON, not "Link not found." — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/redirect/api/RedirectController.java:32` (`/{segment}`); `src/main/resources/application.yml:42-45` (only `server.error.include-*` is set; no custom `ErrorController` exists in `src/main`, so Boot's `BasicErrorController` still owns `/error`).
- **AC / contract:** AC-16b; spec §3 (visitors only ever get a redirect or a plain-text sentence); `openapi.yaml:262-273` (non-redirect answers on this path are text/plain with `no-store`).
- **Problem:** `/error` is a literal path, so it beats `/{segment}`. A direct request has no error attributes, so the answer is HTTP 500 `{"status":999,"error":"None",…}`. Scanners request `/error` often, and every hit counts as `outcome=SERVER_ERROR`, which sad.md §7 treats as a bug signal. `RedirectIT.java:94` does not include `/error`.
- **Raised by:** trace reviewer.
- **Resolution:** Fix now. Replace `BasicErrorController` with a small `ErrorController`. A direct request (no `jakarta.servlet.error.status_code` attribute) outside `/api` gets `VisitorAnswer.Message.NOT_FOUND` (text/plain, `no-store`); real error dispatches keep the Problem Details rendering. Add `/error` to the `RedirectIT` malformed cases.

### P2 — [stage-1, low] `GET /api` and `GET /api/` get the visitor's plain-text answer — **Fix now**

- **Where:** `RedirectController.java:32-35` vs `:44-49`; `src/main/java/io/github/igorermolenko/trimly/redirect/api/VisitorRequestRejectedHandler.java:42` (already treats `/api` as owner API).
- **AC / contract:** `openapi.yaml:24-25` (owner-API errors are Problem Details with a `code`).
- **Problem:** with a valid credential, `/api` and `/api/` match `/{segment}` and look up a short code named `api`, so the owner gets text/plain "Link not found.". Deeper unknown `/api/…` paths already get a Problem 404 (`shared.not_found`).
- **Raised by:** trace reviewer.
- **Resolution:** Fix now. Apply the `"api".equals(segment)` guard in `follow` (throw `ErrorResponseException(NOT_FOUND)`) and add an `OwnerApiContractIT` case.

### P3 — [stage-1, low] The server accepts unknown members in a create request; the contract forbids them — **Fix now**

- **Where:** `docs/features/url-shortener/contracts/openapi.yaml:461-466` (`ShortLinkCreate.additionalProperties: false`) vs `src/main/java/io/github/igorermolenko/trimly/link/api/CreateShortLinkController.java:17` (plain record; the JSON mapper ignores unknown properties, and nothing in `src/main` changes that).
- **AC / contract:** `openapi.yaml:78-86`.
- **Problem:** `{"targetUrl":"https://x.test/","extra":1}` gets a 201. A typo such as `{"targetURL":…}` gets `link.target_url_unsupported`, which misleads the owner. No test pins either behaviour.
- **Raised by:** trace reviewer.
- **Resolution:** Fix now, rejecting unknown members. A create body with an unknown member gets 400 `shared.malformed_request`. Add `CreateShortLinkIT` cases for an extra member and for the `targetURL` typo, and validate the answer against `Problem` in `OwnerApiContractIT`.
