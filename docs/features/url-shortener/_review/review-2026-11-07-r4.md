### Q1 — [stage-1] Tomcat rejects raw `{ } | [ ] ^ \`` in the query or path before trimly sees the request — **Fix now**

- **Where:** `src/main/resources/application.yml:47-50` (no `server.tomcat.relaxed-query-chars` or `relaxed-path-chars`; `grep -r relaxed src/` finds nothing); `src/test/java/io/github/igorermolenko/trimly/redirect/api/RedirectIT.java:50-51` (the query cases use only safe characters).
- **AC / contract:** AC-07 (any query string is ignored), AC-16b (a malformed address gets "Link not found."); `openapi.yaml:262-273`.
- **Problem:** Tomcat answers a request target that contains these characters with its own 400 before the servlet runs. Browsers send `{ } | [ ] ^ \`` unencoded in the query and `| [ ] ^` unencoded in the path. So `/aB3dEf9?a[]=1` never redirects, and `/abc|234` gets no plain-text "Link not found." with `no-store`. This is the same kind of gap as round-1 R3, one layer further out.
- **Raised by:** trace reviewer.
- **Resolution:** Fix now. Set `server.tomcat.relaxed-query-chars` (`{ } | [ ] ^ \` \`) and `relaxed-path-chars` (`| [ ] ^`). `StrictHttpFirewall` plus `VisitorRequestRejectedHandler` then catch whatever is still rejected. Add `RedirectIT` cases sent over a raw socket: a valid code with `?a[]=1` → 302 with the exact `Location`, and `/abc|234` → 404 "Link not found." with `no-store` and no lookup.

### Q2 — [stage-1, low] An https URL that `java.net.URI` refuses gets the AC-03 "only http or https" answer — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/link/domain/TargetUrl.java:44-46` (any `URISyntaxException` maps to `Reason.UNSUPPORTED`).
- **AC / contract:** AC-03, AC-05.
- **Problem:** printable-ASCII characters that pass the AC-05 check but that `new URI` refuses, such as `[ ] { } | ^ \``, `"`, `<`, `>`, a bad escape like `%zz`, or a second `#`, produce `link.target_url_unsupported`. So `https://example.test/?a[]=1` gets "Only absolute http or https web addresses are accepted." AC-05's percent-encoding guidance is the answer that fits.
- **Raised by:** trace reviewer.
- **Resolution:** Fix now. Decide scheme and host before the strict parse, and map an unparseable http(s) address to `Reason.NOT_ENCODED`. Add `TargetUrlTest` cases for `?a[]=1`, `/a|b` and `/100%`, and keep the existing AC-03 cases green.
