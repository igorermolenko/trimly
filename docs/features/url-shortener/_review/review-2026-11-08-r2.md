### S1 — [stage-1, low] A bad percent-escape in a list query parameter gives 500 instead of the contract's 400 — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/link/api/ListShortLinksController.java:24` (`@RequestParam after` / `limit`); `src/main/java/io/github/igorermolenko/trimly/shared/ProblemDetailsAdvice.java:71` (the catch-all `Exception` handler).
- **AC / contract:** AC-09; `openapi.yaml:184-190` (list 400).
- **Problem:** with a valid owner credential, `GET /api/v1/links?after=%zz` or `?limit=%` makes Tomcat 11.0.27's `Parameters.processParameters` fail to decode. `Request.parseParameters` then throws `org.apache.tomcat.util.http.InvalidParameterException` (an `IllegalStateException`) from every `getParameter*` call, without `sendError`. Spring's argument resolution propagates it, and the advice answers 500 `shared.internal_error` and logs an ERROR stack trace. Nothing in `src/` handles that class. This dates from T14; `ListShortLinksIT` uses MockMvc, which never runs Tomcat's parameter parser. Visitor redirects are unaffected (nothing on that path reads parameters).
- **Raised by:** trace reviewer (from the Tomcat 11.0.27 bytecode). The dispatcher confirmed the class is in the jar and that nothing in `src/` handles it.
- **Resolution:** Fix now. Map exactly `InvalidParameterException` (not the broad `IllegalStateException`) to 400 `shared.malformed_request`, which the list 400 already names. Add raw-socket ITs with the owner credential for `?after=%zz` and `?limit=%` that assert 400, the documented `code` and the owner-API no-cache/nosniff headers. Name the trigger in the list 400 description in `openapi.yaml` and add an api-sync-report note.

### S2 — [stage-2, low] The valve rewrites any body-less, server-raised 400, not only address decoding failures — **Fix now (docs only)**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/redirect/api/ServerRejectedAddressValve.java:10-17` (javadoc), `:35-36`; `docs/features/url-shortener/contracts/openapi.yaml:400-406` (`MalformedAddress`), `:312-315`; `src/main/resources/application.yml:54-57`.
- **AC / contract:** AC-16b; `MalformedAddress`.
- **Problem:** a reviewer probe on Tomcat 11.0.27 showed other 400s Tomcat raises with no throwable and no body. Examples: HTTP/1.1 with no `Host` header, with two `Host` headers, or with `Content-Length: abc`. The valve rewrites these too, so `GET /<valid active code>` sent that way gets 404 "Link not found.", and `POST /api/v1/links` gets `shared.malformed_request` ("The request address is not valid."). No browser sends such requests. The code's behaviour is acceptable (it is consistent with hide-existence), but the javadoc and the contract say "while decoding it", which is narrower than what the code does.
- **Raised by:** fix-verification reviewer (embedded-Tomcat probe).
- **Resolution:** Fix now, docs only (the user chose to reword rather than narrow the code). The valve javadoc and comment, `MalformedAddress`, the visitor 404 description and the yml comment should say "a request the server itself rejects before trimly runs (a bad address, a missing or duplicate Host, an unreadable Content-Length)". Add an api-sync-report note. No code change.
