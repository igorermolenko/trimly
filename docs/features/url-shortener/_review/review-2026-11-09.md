### T1 — [stage-1 docs / stage-2, low] The `InvalidParameterException` trigger is described more narrowly than the code handles — **Fix now (docs only)**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/shared/ProblemDetailsAdvice.java:58-63` (javadoc); `docs/features/url-shortener/contracts/openapi.yaml:189-191` (list 400); `docs/features/url-shortener/contracts/api-sync-report.md:48` (T45 note).
- **AC / contract:** AC-09 (and the create 400); T46 DoD (`tasks/docs-server-rejected-request-wording.md:44`, "No doc claims a narrower trigger than the code").
- **Problem:** the docs give one trigger: "the query is not validly percent-encoded". In Tomcat 11.0.27, `InvalidParameterException` is also thrown in these cases:
  - a chunk with an empty name (`parameters.invalidChunk`, for example `?=x` or `?limit=20&=`);
  - more than `maxParameterCount` parameters (`parameters.maxCountFail`);
  - a urlencoded form body over `maxPostSize`, or a form body that cannot be read. Spring's `ServletServerHttpRequest.getBody()` reads the parameter map on a form `POST /api/v1/links`, so these reach the handler too.

  All of these get 400 `shared.malformed_request`, which the contract allows; only the wording is narrower. Separately, the javadoc says Tomcat throws "on every parameter read". A query decode failure is in fact thrown only on the first `getParameter*` call (`Request.doParseParameters` sets `parametersParsed=true` first), and later calls return partial parameters. Today this is harmless, because the first read is the handler's `@RequestParam`, but the comment would mislead a future filter author.
- **Raised by:** both reviewers, independently (from the Tomcat 11.0.27 bytecode). The dispatcher confirmed that the `parameters.invalidChunk` and `parameters.maxCountFail` messages are in the jar.
- **Resolution:** Fix now, docs plus one test case. Reword the advice javadoc, the openapi list 400 and the api-sync note to "the server cannot read the request's parameters (a query that is not validly percent-encoded such as `?after=%zz` or a lone `%`, a parameter with an empty name such as `?=x`, too many parameters, or an unreadable form body)". Change "every parameter read" to "the first parameter read". Add `?=x` to the `ProblemDetailsAdviceIT` cases. No behaviour change.
