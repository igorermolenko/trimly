### R1 — [stage-1] Storage budget split turns a 0.95–1.9 s wake into "unavailable" — **Fix now**

- **Where:** `src/main/resources/application.yml:18` (`connection-timeout: 950`), `:20` (`statement_timeout = 900`), `:22-24` (driver timeouts 1 s).
- **AC / contract:** AC-17 ("storage that is waking from idle and answers within the 2 seconds is not unavailable"), AC-17b; feature ADR-0003 (connect + wake share ≈ 1.2–1.5 s); `sad.md:142`; `tasks/storage-time-budget-and-draining-pool.md:91`.
- **Problem:** connection acquire is capped at 950 ms, below the planned split. Because the pool drains when idle (`minimum-idle: 0`), the first request after idle opens a new connection, so a cold Neon wake of 0.95–1.9 s gets a 503 even though it fits inside 2 s. The test-plan row "slow but answering storage is not an outage" (`test-plan.md:63`) has no test; `StorageOutageIT.java:90-108` covers only a full outage.
- **Raised by:** all three reviewers.
- **Resolution:** Fix now. Re-split toward ADR-0003 (acquire ≈ 1.2 s, server-side `statement_timeout` ≈ 600 ms, worst case ≈ 2 s; record the whole-second `socketTimeout` limit), and add the IT: pause storage ≈ 1 s, unpause, expect a normal 302.

### R2 — [stage-1] Localhost defaults let the AC-06 loop guard fail open — **Fix now**

- **Where:** `src/main/resources/application.yml:32-35`; `src/main/java/io/github/igorermolenko/trimly/link/app/LinkProperties.java:17-30`; `link/domain/TargetUrl.java:56-61`.
- **AC / contract:** AC-06 ("including one of trimly's own short links"), AC-01 (`shortUrl` built from `trimly.public-base-url`); `sad.md` §8 Configuration ("validated at startup, failing fast").
- **Problem:** the main config defaults `public-base-url` to `http://localhost:8080` and `own-hosts` to `[localhost]`, and `LinkProperties` never checks that the public host is one of the own hosts. If production sets `TRIMLY_PUBLIC_BASE_URL` but forgets `TRIMLY_OWN_HOSTS`, a target on trimly's own public host is accepted (a redirect loop). If it forgets the base URL, trimly issues localhost short links. The test contexts already show the mismatch (`link/api/ListShortLinksIT.java:37`).
- **Raised by:** all three reviewers.
- **Resolution:** Fix now. Always treat `publicBaseUrl.getHost()` as an own host (or refuse to start when it is not covered), move the localhost defaults into the test/dev config so production must set both, and add `LinkPropertiesTest` cases.

### R3 — [stage-1] Firewall-rejected visitor paths get a bare 400, not "Link not found." — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/access/api/SecurityConfiguration.java:29-48` (no `RequestRejectedHandler`; the default `StrictHttpFirewall` + `HttpStatusRequestRejectedHandler` sends 400).
- **AC / contract:** AC-16b (malformed code, including trailing punctuation → "Link not found."); `openapi.yaml` `GET /{shortCode}` ("Every answer on this path carries `Cache-Control: no-store` … never Problem Details").
- **Problem:** `/aB3dEf9;`, `/aB3dEf9;x=1`, `/aB3dEf9//`, and paths with encoded `%25` or `%2F` never reach `RedirectController`; they get a bodyless 400 with no `no-store`. `RedirectIT.java:77` only covers malformed codes that pass the firewall.
- **Raised by:** contract + conventions reviewer; security + edges + tests reviewer.
- **Resolution:** Fix now. Register a `RequestRejectedHandler` that answers 404 `text/plain;charset=UTF-8` "Link not found." with `Cache-Control: no-store` outside `/api/**` (400 Problem Details kept for `/api/**`), and add these paths to the RedirectIT malformed cases.

### R4 — [stage-1] Wrong Content-Type on create returns 415 without `code` — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/shared/ProblemDetailsAdvice.java:27-38`.
- **AC / contract:** `openapi.yaml` `POST /api/v1/links` 400 `shared.malformed_request`; `contracts/api-sync-report.md` flag F1 ("not a JSON object (or has a wrong content type)" → override `handleHttpMediaTypeNotSupported` and set the code).
- **Problem:** only `handleHttpMessageNotReadable` is overridden. A `text/plain` or missing-Content-Type body falls to Spring's default 415 Problem Details, which has no `code`. No IT covers it.
- **Raised by:** contract + conventions reviewer.
- **Resolution:** Fix now. Override `handleHttpMediaTypeNotSupported` to answer 400 `shared.malformed_request`; add a `CreateShortLinkIT` case.

### R5 — [stage-1] Some owner-API Problem responses have no `code` — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/shared/ProblemDetailsAdvice.java:40-44` (generic 500); `src/main/java/io/github/igorermolenko/trimly/redirect/api/RedirectController.java:40-43` (unknown `/api/...` path → bare 404, owner-API handling sitting in the `redirect` module); the inherited `ResponseEntityExceptionHandler` answers (405, 406, 415).
- **AC / contract:** `openapi.yaml:406` `components.schemas.Problem.required: [type, title, status, code]`.
- **Problem:** these answers are Problem Details without the required `code` member.
- **Raised by:** contract + conventions reviewer.
- **Resolution:** Fix now. In the shared advice, set a fallback `code` on every `ProblemDetail` it emits (e.g. `shared.internal_error`, `shared.not_found`, `shared.method_not_allowed`) and add those values to the contract enum.

### R6 — [stage-1, low] Health endpoint is not the liveness-only group ADR-0006 specifies — **Fix now**

- **Where:** `src/main/resources/application.yml:50-53`.
- **AC / contract:** feature ADR-0006 ("Health checks use a liveness-only group with no database indicator"); `sad.md:438`, `:475`.
- **Problem:** only the `db` indicator is disabled. `/actuator/health` still combines every other indicator, and no `liveness` group is exposed off Kubernetes/Cloud Foundry, so Fly has no `/actuator/health/liveness`.
- **Raised by:** contract + conventions reviewer.
- **Resolution:** Fix now. Enable the health probe groups (or an explicit `liveness` group of `livenessState` + `ping`) and add an IT asserting `/actuator/health/liveness` is UP while storage is paused.

### R7 — [stage-2] Disabling Security's Cache-Control writer removes no-cache from the owner API — **Fix now**

- **Where:** `src/main/java/io/github/igorermolenko/trimly/access/api/SecurityConfiguration.java:46-47`.
- **AC / contract:** spec §6.1 (the owner's list is not public); `sad.md` §8 "Redirect reuse"; feature ADR-0001 ("adds safe default headers").
- **Problem:** `CacheControlHeadersWriter` already skips a response that has `Cache-Control` (spring-security-web 7.1.2), so the redirect's `no-store` was never at risk. Disabling the writer app-wide drops the no-cache headers from `GET /api/v1/links`, the 401s and the disable/enable answers.
- **Raised by:** contract + conventions reviewer; security + edges + tests reviewer.
- **Resolution:** Fix now. Remove the `cacheControl.disable()` line (RedirectIT's exact `no-store` assertion still guards redirects) and add an IT asserting `no-store` on `GET /api/v1/links`.

### R8 — [stage-2] Flyway inherits the request time budget — **Fix now**

- **Where:** `src/main/resources/application.yml:18-24`.
- **AC / contract:** feature ADR-0003 (the 2 s budget is scoped to link-storage calls).
- **Problem:** Flyway shares the Hikari DataSource, so migrations run under `SET statement_timeout = 900`, `socketTimeout=1` and the 950 ms acquire limit. A future long migration, waiting on another instance's migration lock, or a slow wake at startup would stop trimly from starting.
- **Raised by:** security + edges + tests reviewer.
- **Resolution:** Fix now. Give Flyway its own connection settings (`spring.flyway.url/user/password`, without the init SQL or socket timeout), so the request budget applies only to link-storage calls.
